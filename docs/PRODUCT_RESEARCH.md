# 大肥鱼产品依据与取舍 · 2026-11-01

本轮纠正了0.1.x泛陪伴“回声”的定位。目标是把大家熟悉的DeepSeek社区大肥鱼养进QQ，产品工作集中在角色识别、接梗体验、安装整合和可靠运行；不宣称重新训练模型或创造了底层角色。

## 已核实的一手材料

- [腾讯QQ：听说最近大家都在QQ养大肥鱼！](https://www.bilibili.com/video/BV17rxT6UEpH)：简介署名上善无形（形象原型）、ZipZipPipe（女仆二次设计）、这个刀子真甜（Q版参考）。这证明QQ养鱼已形成具体传播场景，不能证明用户看到的一定是这条视频。
- [DeepSeek官方Harness](https://github.com/deepseek-ai/deepseek-harness)：官方开源Agent Harness，插件架构，开发者预览。
- [腾讯官方QQ插件](https://github.com/tencent-connect/dsh-qqbot)：官方QQ Bot绑定、QQ消息交给DSH agent loop，再由插件发送回复。此前只研究NapCat路线是不完整的。
- [大肥鱼AstrBot整合](https://github.com/whyever77/dafeiyu-astrbot)与[使用者自己的搭建记录](https://www.soki.moe/posts/astrbot-napcat-qq)：人格、短句分段、记忆和主动联系构成“养鱼”实践，配置和下载仍可能耗时。是实践样本，不能推算市场规模。
- [社区视觉一致性工具](https://github.com/Neko3000/deepseek-whalechan)：整理渐变蓝发、呆毛、鲸鳍、鲸尾、女仆服等视觉锚点；该项目具体比例与生日等不是全网官方定稿。
- [ZipZipPipe本人声明](https://www.bilibili.com/opus/1247156596114456581)：角色CC BY-NC-SA4.0。新生成衍生图不自动抹去这条来源链。
- [DeepSeek模型API](https://api-docs.deepseek.com/api/create-chat-completion/)：当前正式模型deepseek-flash/deepseek-v4-pro。不能沿用老仓库枚举就声称兼容当前服务。

部分B站页面直读412，使用公开平台适配器核对了标题、作者、简介和评论；没有声称逐帧看完所有视频。最早“模型自称大肥鱼”的原始截图未独立验证，不编造起源史。

## 体验决定

| 观察 | 实现 |
| --- | --- |
| Q版大头、渐变蓝发、鲸鳍尾、女仆装有辨识度 | 统一生成主视觉与三种反应表情，首屏让角色与聊天成为主体 |
| 白饭、摸鱼、被戳穿嘴硬和AI元幽默是反复出现的梗 | 四档语气共享角色身份，经典档适量接梗；不每句提米饭、不套刻板辱骂或默认恋爱 |
| 真实陪伴依赖连续相处 | 有界短期上下文与拥有者确认的长期记忆；不编造共同经历 |
| 虚构漫画的偷懒/瞎编不是实际质量要求 | 认真任务优先准确，承认不确定；不故意答错、删文件或拖延 |
| 同一个模型API可以被不同运行环境组织成不同体验 | 明确区分基础模型、人格上下文、记忆、QQ传输和可选Harness工具；不把换头像说成新模型 |
| 传播可能来自真实对话与表情反应 | 本版先提供明确标识的三场景样例；它们不是伪造的用户聊天或真实模型评测 |

## 技术与发布边界

聊天台是独立Node/SQLite/OneBot实现，提供固定版本的官方DSH可选安装入口。两者不自动共享设置与记忆。先复用成熟生态完成可验证的安装与接入，不为追热点临时编造云端能力。

记忆删除/暂停让在途结果失效、消息去重、用量未知如实标记、发送未知不重试继续作为底层品质。合成测试不等于QQ实际收信；没有Windows实机、国内网络与服务器证据时明确pending。多租户托管依照HOSTING.md单独评估。
